# Unofficial Hyperbeam for Android

A native Android client for [Hyperbeam](https://hyperbeam.com) watch parties.
It runs the real Hyperbeam site and fixes the parts that are rough on a phone:

- **Typing into the shared browser works.** The app takes over the keyboard and
  sends real key presses, so autocorrect, swipe typing, voice typing and emoji
  all reach the shared browser. An extra-keys row adds Esc, Tab, Ctrl, Alt,
  Shift, arrows, Home/End and paste, and a compose box lets you write a full
  line before sending it. Hardware keyboards pass through with modifiers.
- **It keeps running in the background.** The room lives in a foreground
  service with a persistent notification, so switching apps or turning off the
  screen doesn't stall or drop it.
- **Recent chat in the notification.** The persistent notification shows the
  room's latest messages in conversation style, with a reply box that posts to
  the room's chat.
- **No account needed.** The start screen joins a room by name or link
  (`/r/<name>`), which only asks for a display name. Recent rooms are kept on
  the device.
- **Links open in the app.** Hyperbeam links open here, and sharing a URL from
  another app types it into the shared browser's address bar.

Not affiliated with Hyperbeam, Inc.

## Install

Every push builds APKs in GitHub Actions. Open the latest run under
**Actions → Build**, download the `hyperbeam-…` artifact, and install the APK.

## How it works

```
Android shell (Kotlin)            WebView: hyperbeam.com/app
  RoomSession  (owns WebView) ─┐    ┌─ Hyperbeam site (unchanged)
  RoomService  (foreground)    │    │
  HbWebView + RemoteInput ─────┼─JSON─ bridge.js (injected, shared)
  MainActivity (keyboard bar)  ┘    └─ hooks the streaming client's input
```

- `bridge/` is a TypeScript script injected at document start into
  hyperbeam.com pages only. It captures Hyperbeam's streaming client (the module
  that `@hyperbeam/web` loads) so the app can send key events through the same
  path the site uses, keeps the page reporting itself as visible, tells the app
  when the site's own text fields take focus, and can export a debug snapshot.
  It is platform-neutral so an iOS shell could reuse it.
- `core/` is plain Kotlin with no Android dependency. `TextSync` turns IME
  buffer changes into the arrows, backspaces and characters that make the
  remote text field match.
- `app/` is the Android shell.

## Develop

```sh
# Bridge script: type-check, test in headless Chromium, rebuild the bundled asset
cd bridge && npm ci && npm run typecheck && npm test && npm run build

# Platform-neutral Kotlin (no Android SDK needed)
./gradlew -p core test

# Android app (needs the Android SDK)
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

`app/src/main/assets/bridge.js` is generated by `npm run build` and committed so
the Android build doesn't need Node. CI checks that it's up to date.

### Release signing

Release APKs are signed with the debug key unless these repository secrets are
set: `HB_KEYSTORE_BASE64` (base64 of a `.jks`), `HB_KEYSTORE_PASSWORD`,
`HB_KEY_ALIAS`, `HB_KEY_PASSWORD`. With them, every build installs over the
previous one.

### Debug snapshot

Menu → *Share debug snapshot* saves the page's structure, script URLs and a
short sample of its WebSocket traffic to a JSON file you can share. It's how
features that depend on Hyperbeam's undocumented internals (like reading chat)
get built. It contains your room's page and chat traffic, so only share it with
people you trust.
